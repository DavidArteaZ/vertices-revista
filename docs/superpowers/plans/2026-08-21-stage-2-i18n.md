# Stage 2 — i18n migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans.

**Goal:** Replace the runtime DOM-swapping translator with server-rendered
next-intl locale routes, without moving a single pixel in any of the six
languages.

**Architecture:** Semantic, component-namespaced keys. A generator script maps
`key → Spanish literal → the five legacy dictionaries` and bakes the
Spanish-fallback into every locale file, so a missing translation renders
exactly what the legacy site renders today.

**Tech Stack:** next-intl, Next.js 16 App Router, Playwright, Vitest.

**Spec:** `docs/superpowers/specs/2026-08-20-vertices-nextjs-supabase-design.md` §11

## Global Constraints

- Six locales: `es` (root), `en`, `fr`, `it`, `pt`, `ru`.
- `<option value>` attributes stay **Spanish** in every locale. Only the label
  is translated. The database receives Spanish regardless of locale.
- The language pill keeps its current appearance exactly
  (`web/src/app/selector-idioma.css`).
- The visual gate is the existing golden baselines captured from the legacy
  site in stage 1. **Do not regenerate them against the new app.**
- Tolerance stays `maxDiffPixelRatio: 0.001`. If a locale fails, fix the cause.

## The research this plan rests on

Measured, not assumed:

| | |
|---|---|
| union of the five legacy dictionaries | 517 keys |
| `ru` / `en` / `it` / `fr` / `pt` | 517 / 511 / 509 / 508 / **479** |
| keys containing a `.` | **235** — cannot be next-intl dot paths |
| distinct strings the ported app actually renders | **458** |
| of those, absent from *every* legacy dictionary | **59** |

The 59 are overwhelmingly untranslatable by design — `Vértices`, `ES`,
`English`, `←`, `✕`, digits, an email address, and the 26 placeholder article
titles and author names. A handful are real gaps the legacy site also has
(`"Aún no lo decido"`, `"Otro tema"`, the IA-usage paragraph): the legacy
renders Spanish there in every language, and so must we.

### Decision 1 — the fallback is baked at build time, not resolved at runtime

Legacy does `dicc[s] || s`. The generator does the same, once:

```js
mensajes[locale][clave] = dictLegado[locale][espanol] ?? espanol
```

Every locale file therefore carries **all** keys. Portuguese's 38 missing
translations become 38 Spanish strings — byte-identical to what
`pt` renders today. Consequences: the CI key-set check is trivially satisfiable
and still meaningful (it catches a key added to a component but not
regenerated), and next-intl can never throw `MISSING_MESSAGE` in production.
`defaultLocale: "es"` is still configured, as defense in depth.

### Decision 2 — keys are auto-generated, namespaced per component

Hand-authoring 458 semantic keys is a day of typing and a fresh source of
error. The generator derives `"<namespace>.<slug of the Spanish text>"`, e.g.
`convocatoria.el_punto_donde_las_ideas_se_conectan`. Namespace comes from the
source file. Long strings truncate to 48 chars plus a 4-char content hash, so
paragraphs get stable, unique, greppable keys.

**This structurally resolves the collisions §11 flags.** `"Otro"` in the
*género* select and `"Otro"` in a *formato* select land in different
namespaces, so each gets its own translation slot. Both are seeded with the
same legacy translation, because changing either changes rendered text and
breaks the gate. Retranslation is the committee's call, and the structure now
allows it without a migration.

### Decision 3 — two translation surfaces, one catalog

1. **Static JSX text** — `t("key")`, server-rendered. This is the bulk.
2. **Dynamic strings** — the particle engine's node labels, the wizard's
   validation messages, the discovery panel's counters, the status lookup's
   replies. These are `TR(...)` calls in the legacy
   (`index.html:1261,1302,1953-1962,2072-2094,2219-2347`). They become ordinary
   `t()` calls with semantic keys at the call site; `motor.ts` receives a
   `traducir` function through `MotorOpciones` instead of its identity `TR`.

Engine data labels key off the data, not the sentence: `temas.<slug>`,
`secciones.<slug>.label`, `secciones.<slug>.desc`.

### Decision 4 — interpolation stays legacy-shaped

Legacy writes `TR("{n} de {m} temas").replace("{n}", …)`. ICU uses the same
brace syntax, so these strings port verbatim as ICU messages.

Legacy branches manually on `n === 1` for plurals (`"1 artículo"` vs
`"{n} artículos"`). **Keep the branch. Do not convert to ICU `plural`.** Russian
has three plural forms and Portuguese has different rules; an ICU plural would
render text the legacy never produced and fail the gate.

**Hazard:** ICU treats `'` as an escape character before `{`, `}`, `#`, or
another `'`. French translations are full of apostrophes. A lone `'` is safe,
but `d'{n}` is not. The generator refuses to emit any message containing `{`
or `}` unless its key is in an explicit `PARAMETRIZADOS` allowlist, and
escapes stray apostrophes adjacent to braces.

### Decision 5 — placeholder article data is not translated

The 26 demonstration articles (`src/lib/datos/articulos.ts`) appear in no
dictionary. Legacy renders them in Spanish in every locale. They render raw.
Adding keys for them would be inventing content.

## File Structure

```
web/
  scripts/
    i18n/
      dicts.mjs            load the five legacy dictionaries in a vm sandbox
      cosechar.mjs         harvest rendered strings from a running app
      generar.mjs          key generation + messages/*.json emission
      verificar.mjs        CI: all six files share one key set
  messages/
    es.json en.json fr.json it.json pt.json ru.json
  src/
    i18n/
      rutas.ts             LOCALES, defaultLocale, localePrefix
      peticion.ts          getRequestConfig
      navegacion.ts        Link/redirect/usePathname/useRouter wrappers
    middleware.ts
    app/
      [locale]/
        layout.tsx  page.tsx  globals.css  selector-idioma.css
        lineamientos/  quienes-somos/  equipo/
```

Everything under `src/app/` moves one level into `[locale]/`. `localePrefix:
"as-needed"` keeps Spanish at `/` and the redirect map from stage 1 intact.
