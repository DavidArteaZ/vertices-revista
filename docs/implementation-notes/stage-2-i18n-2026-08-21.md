# Implementation notes — Stage 2, i18n migration

- **Spec**: `docs/superpowers/specs/2026-08-20-vertices-nextjs-supabase-design.md` §11
- **Plan**: `docs/superpowers/plans/2026-08-21-stage-2-i18n.md`
- **Started**: 2026-08-21

## Decisions made outside the plan

- **The Spanish fallback is baked at generation time, not resolved at
  runtime.** `messages/*.json` is emitted by `scripts/i18n/generar.mjs` as
  `dictLegado[locale][español] ?? español`, so all six files carry all 499
  keys. Portuguese's missing translations become Spanish strings — byte-equal
  to what `pt` renders today, since the legacy resolves the same fallback at
  runtime with `dicc[s] || s`. Consequences worth knowing: next-intl can never
  raise `MISSING_MESSAGE` in production, and the CI key-set check is
  trivially satisfiable, so what it actually catches is a key added to a
  component without regenerating, or a hand-edited message file.
- **Keys are generated from the Spanish text, not hand-authored.** 499 keys is
  a day of typing and a fresh source of typos. `claveDe()` slugs the string
  and truncates at 48 chars with a 4-char content hash. Collisions inside one
  namespace between *different* strings — `"tu correo"` (placeholder) and
  `"Tu correo"` (aria-label) on the same input, which the legacy translates
  separately — get the hash appended.
- **The conversion is a codemod over the TypeScript AST**
  (`scripts/i18n/convertir.mjs`), not regex and not hand edits. It needs exact
  JSX node positions and it must split text at exactly the boundaries
  `idiomas.js`'s TreeWalker splits at, so that inline `<strong>` and `<a>`
  produce their own keys — that is what the legacy dictionaries are keyed on.
  It implements React's own whitespace-collapsing rules to compute the
  rendered text before slugging it.
- **Strings with no letters are never translated** — `"27"`, `"✕"`, `"←"`,
  `"·"`. They are in no legacy dictionary and would only add keys whose value
  is the same in six files.
- **`validarPaso` returns a key, not a sentence.** It now yields
  `{ clave, valores? }` against the `avisos` namespace. The original called
  `TR()` on the literal, which is the same mechanism; separating the message
  from the judgement is also what stage 4 needs, since the server has to write
  the error in the *author's* stored locale, not the request's.
- **Topic and section labels key off `slug(español)`**, computed at runtime by
  `src/i18n/catalogo.ts` from the data itself. They are data, not interface
  copy — the database stores them in Spanish — so the Spanish literal stays in
  the code and only the rendering is translated.
- **The engine keeps its `TR`.** `motor.ts` receives `traducir` through
  `MotorOpciones` and `useCatalogo` supplies it. This is the same shape as the
  original's `window.__dicc` lookup, which keeps the verbatim port verbatim.
  `traduceEtiquetas()` runs *after* `buildNetwork`/`buildSections` rather than
  inside them, as the original does, because the visual gate compares the
  order in which both sides consume `Math.random` and translating inside would
  not change it — but keeping the call out of those functions makes that
  impossible to get wrong later.
- **`__alCambiarIdioma` is gone.** It existed so `idiomas.js` could rewrite the
  DOM in place. The locale is now the URL and a page never changes language
  without remounting.

## Deviations from the plan

- The plan's Tasks 3–9 were done as one sweep per surface rather than as nine
  separately-committed tasks. The gate is what makes a step safe here, and it
  runs over the whole app; splitting the commits would not have made any
  individual step verifiable on its own.
- **`middleware.ts` is `proxy.ts`.** Next 16 renamed the convention and warns
  on every start. Not in the plan because the warning only appeared once
  next-intl's middleware was actually wired.

## Bugs found and fixed that were not i18n

Both were found by making the satellite visual gate honest. Neither would have
been caught by reading the diff.

- **`backdrop-filter` was dead on every blurred surface.** Lightning CSS, given
  both `backdrop-filter` and `-webkit-backdrop-filter` in a rule, "optimises"
  by emitting only the prefixed one. Chrome 151 removed that alias entirely —
  `CSS.supports("-webkit-backdrop-filter", "blur(1px)")` is `false` — so all 19
  rules computed to `none`. Removing the hand-written prefix from the source
  makes Lightning autoprefix properly and emit both. **This shipped broken in
  stage 1** and would have shipped to production. Watch for the same shape with
  any other prefixed/unprefixed pair; `-webkit-appearance` was checked and is
  still honoured.
- **The engine passed only the translated node label to the panel**
  (`index.html:1920`), and `articulosDe()` matches against Spanish data. In any
  non-Spanish locale, clicking a constellation node showed "no articles yet"
  for every topic. `alAbrirPanel` now carries `label0` alongside `label`. Fixed
  rather than reproduced because stage 6 points this panel at the database,
  where it stops being cosmetic.

## Gotchas / surprises

- **Stage 1's satellite baselines were never reproducible.** Its note claimed
  they "pass at zero tolerance because the per-frame veil changes less than one
  quantization step". Measured: two consecutive captures of the same page, with
  the RNG already seeded, differ by ~140,000 pixels. The flow field accumulates
  one trail per frame and the frame count depends on load time — the same
  defect as `autoAng` on the landing. Stage 1 passed by luck.
  Fixed by capturing under `prefers-reduced-motion`, whose branch in
  `fondo-flujo.js` runs 1100 synchronous fixed-`dt` steps and stops, touching
  rAF never. Legacy against legacy is now 0 pixels. It is not a test-only code
  path: it is what anyone browsing with reduced motion sees.
- **A `fullPage` screenshot resizes the viewport, which restarts the flow
  field.** `fondo-flujo.js` debounces `resize` by 200 ms and reseeds. Whether
  that fires before the shutter is a race — and it raced on *both* sides, so
  failures moved between locales run to run (es/it/ru one time, none of those
  three the next). `preparaSatelite()` now provokes the resize deliberately and
  waits the debounce out, so both sides go through exactly one restart and the
  viewport already matches the document by the time the shutter opens.
- **`__resembrar()` must fire only on the *first* start**, not on every
  `arranca()`. The legacy does not reseed on resize; reseeding on the
  capture-induced resize put the two sides back out of sync. Showed up only on
  `lineamientos`, the tallest page, where the debounce has time to fire.
- **A stable-frame timeout is not a pixel difference.** One run reported four
  failures, all `Timeout 5000ms exceeded`, with individual tests taking 30 and
  72 minutes — a second Playwright run was competing for the CPU. Zero pixels
  differed in any of them. `toHaveScreenshot.timeout` is now 30 s; the pixel
  tolerance is untouched.
- **`<meta name="description">` is now translated and was not before.**
  `idiomas.js` only walks `document.body` plus `document.title`, so the
  description stayed Spanish in every locale. It happens to be in the
  dictionaries, so the generator picked it up. Invisible, and an improvement,
  but it is a behaviour change.
- **The equipo page needed its own `layout.tsx`** to carry a localized
  `<title>`: the page is a client component (it calls `history.back()`), and
  client components cannot export metadata. The legacy declares the title and
  `idiomas.js` translates it like any other string.
- **The topic filter searches the translated text**, not the Spanish. Typing
  "trade" in English now finds Comercio Internacional. The legacy filtered the
  Spanish while displaying the translation, so in English the filter appeared
  to match nothing.

## Deferred / follow-ups

- **The collisions §11 flags are structurally resolved but not retranslated.**
  `"Otro"` in the *género* select and any other same-string-different-meaning
  pair now occupy separate keys, and each can be given its own translation
  without a migration. They are seeded with the *same* legacy translation on
  purpose: changing one changes rendered text and fails the gate. Correcting
  them is the committee's call, and it is now a one-line edit to
  `scripts/i18n/claves.json` per key.
- **The nine `tipos_pieza` labels from spec §8 are not added yet.** They
  replace the current five `formato` options, which is stage 4's change; they
  will need new translation work in all five languages.
- The 26 placeholder articles' titles and author names are rendered untranslated
  in every locale, exactly as today. They are demonstration content and appear
  in no dictionary.

## Open questions for review

- **67 strings render in Spanish for Portuguese readers** (36 for Russian, 42
  for English), because the legacy dictionaries never covered them. This
  matches today's behaviour exactly, which is why the gate passes — but it is
  now visible and countable, and `npm run i18n:generar` prints the tally per
  language. Worth deciding whether to commission the missing translations
  before launch.
- **Language choice is no longer remembered.** The legacy persisted it to
  `localStorage`; now the URL is the state, so a shared link always opens in
  the language the link names. A returning visitor lands on Spanish unless they
  bookmarked a prefixed URL. Deliberate, and reversible with a cookie if the
  committee disagrees.
